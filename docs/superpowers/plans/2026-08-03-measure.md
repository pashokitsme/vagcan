# `vagcan measure` implementation plan

> **For agentic workers:** the design is
> `docs/superpowers/specs/2026-08-03-measure-design.md`. Read the sections your task names
> before writing code. Where this plan and the spec disagree, the spec wins — say so in your
> report rather than silently choosing.

**Goal:** time acceleration runs from the car's own speed signal, with a live terminal view, a
saved session, and a generated chart page.

**Architecture:** a fixed channel set resolved by catalog *name*, polled in two batches at
different cadences over the existing `watch` polling stack; a pure state machine that turns
samples into runs; a pure numeric layer that turns a finished run into marks, acceleration,
peaks, shifts and power; and three renderers (live screen, results table, HTML page).

**Tech stack:** Rust edition 2024, tokio, ratatui 0.29, serde_json, `vag-can` / `vag-protocol`
/ `vag-data` from this workspace.

## Global constraints

- **No car-specific data in code.** Channels resolve by catalog name; identifiers, ratios,
  masses, drag coefficients and pedal thresholds never appear as literals. A constant is
  admissible only as a property of a published standard, cited at the point of use.
- **Read-only.** No new UDS service. `measure` never sends `0x10`.
- **`cargo test --workspace` green and `cargo clippy --workspace --all-targets -- -D warnings`
  clean at the end of every task.**
- Commit messages: Conventional Commits, `Assisted-By:` trailer, never `Co-Authored-By:`.
- Every public item carries a doc comment saying *why*, in the register of the surrounding
  code: plain prose, no marketing, no restating the signature.
- Tests are behavioural and named as sentences, matching the existing style in
  `crates/vagcan/src/watch/plan.rs`.

## Shared types — Task 1 defines these, everything else consumes them

```rust
// crates/vagcan/src/measure/types.rs
pub type Seconds = f64;

/// A numeric channel: values with their own timestamps, columnar because that is
/// how the session file and the chart page both want them.
#[derive(Clone, Debug, Default, PartialEq)]
pub struct Track { pub t: Vec<Seconds>, pub v: Vec<f64> }

/// A discrete channel — gear, selector. Values are the catalog's own labels,
/// never codes: the codes are neither ordered nor contiguous.
#[derive(Clone, Debug, Default, PartialEq)]
pub struct States { pub t: Vec<Seconds>, pub v: Vec<String> }

impl Track {
    pub fn push(&mut self, t: Seconds, v: f64);
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    /// Linear interpolation onto an arbitrary time, `None` outside the span.
    pub fn at(&self, t: Seconds) -> Option<f64>;
    /// The first time the value crosses `target` rising, interpolated.
    pub fn crossing(&self, target: f64, after: Seconds) -> Option<Seconds>;
    pub fn window(&self, from: Seconds, to: Seconds) -> Track;
}

impl States {
    pub fn push(&mut self, t: Seconds, v: impl Into<String>);
    /// The label in force at `t` — a step function, never interpolated.
    pub fn at(&self, t: Seconds) -> Option<&str>;
    /// Label transitions, in order.
    pub fn transitions(&self) -> Vec<(Seconds, String, String)>;
}
```

Read spec §1 (t0), §3 (everything else), §3a.

**Files:** Create `crates/vagcan/src/measure/derive.rs`.

**Interfaces produced:**

```rust
pub enum Scheme { Causal, Central }

/// One acceleration estimate: the slope, the time it is valid at, the span of
/// samples it was fitted over, and its own standard error.
pub struct Slope { pub a: f64, pub t: Seconds, pub span: Seconds, pub sigma: f64 }

/// First-order least squares against each sample's own timestamp.
/// `None` when the window holds fewer than three samples.
pub fn slope(track: &Track, index: usize, window: Seconds, scheme: Scheme) -> Option<Slope>;
pub fn accel_series(track: &Track, window: Seconds, scheme: Scheme) -> Vec<Slope>;

/// The launch instant, and the one-signed bias band on it.
pub struct Start { pub t: Seconds, pub bias_low: Seconds, pub bias_high: Seconds }
pub fn start(track: &Track) -> Option<Start>;

pub struct Peak { pub value: f64, pub t: Seconds, pub sigma: f64 }
pub fn peak(series: &[Slope], tau: Seconds, window: Seconds) -> Option<Peak>;

pub struct Shift {
    pub t: Seconds, pub from: String, pub to: String,
    pub speed_deficit_ms: f64, pub cost_on_mark_s: f64,
}
pub fn shifts(gear: &States, accel: &[Slope], accel_at_mark_top: f64) -> Vec<Shift>;

pub fn distance_m(track: &Track, from: Seconds, to: Seconds) -> f64;

/// A bound on the unit's refresh period, from the intervals between distinct
/// values on the leading channel. Bound, not measurement — say so to callers.
pub fn refresh_bound(track: &Track) -> Option<Seconds>;

/// The 1σ uncertainty of a rolling mark: √2·T_refresh/√12.
pub fn rolling_mark_sigma(refresh: Seconds) -> Seconds;
```

**Required behaviour, each of which is a test:**
- `slope` uses each sample's own timestamp; jittered timestamps on a known ramp still recover
  the ramp's slope.
- Causal and central differ in **phase only**: on a symmetric synthetic peak they return the
  same magnitude at their respective attachment times.
- A 0.3 s cosine dip of 3.0 m/s² sampled at 21 Hz comes back at **≈ 2.2 m/s²** — the
  least-squares differentiator's response `(3/x²)|sin x/x − cos x|`, not `sinc(πfW)`.
- `start` on a **constant-jerk launch with a dead band** (samples below 2 km/h suppressed):
  the returned `t` is never later than the fit puts it — **there is no lower clamp** — and
  `bias_low/bias_high` are both ≥ 0, i.e. the band is one-signed.
- `start` on a constant-acceleration trace must **not** be used as the only test: linear
  extrapolation is exact there and the test would be vacuous.
- `peak` never returns a sample whose `span` is below 0.6·window; an injected noise spike in
  the first 0.1 s does not become the peak.
- `peak` under-reads a synthetic parabolic peak of curvature `c` by `c·τ²/6`, asserted.
- `shifts`: the baseline is the acceleration in the gear being entered; the divisor is
  `accel_at_mark_top`; the window comes from `gear.transitions()`; a trace with no transition
  yields no shift; transitions into or out of a non-numeric label (`"not engaged"`, `"R"`) are
  not shifts.
- `distance_m` uses each interval's own `Δt`; a constant-acceleration trace integrates to the
  closed-form distance within 1 mm.
- `rolling_mark_sigma` depends on the refresh period and **not** on the sample interval.

**Acceptance:** no I/O, no `Instant::now()`, no catalog access, ~25 tests, all offline.

## Task 3 — the dynamics (`measure/power.rs`)

Read spec §3 (Power), §3a.

**Files:** Create `crates/vagcan/src/measure/power.rs`.

```rust
/// Air density from the car's own barometer and ambient sensor.
/// ρ = p/(R·T), R = 287.05287 J/(kg·K) for dry air (ISO 2533).
pub fn air_density(pressure_kpa: f64, ambient_c: f64) -> f64;

pub struct Inertias { pub wheels_kgm2: f64, pub engine_kgm2: f64 }
/// δ₁ = I_wheels/(m·r²), δ₂ = I_engine/(m·r²) — computed from *this* car's mass
/// and radius, never taken as universal constants.
pub fn deltas(i: &Inertias, mass_kg: f64, radius_m: f64) -> (f64, f64);

pub struct RoadLoad { pub cda: f64, pub crr: f64 }
pub struct Conditions {
    pub mass_kg: f64, pub rho: f64, pub grade_percent: f64, pub headwind_ms: f64,
    pub inertias: Inertias, pub radius_m: f64,
}

pub struct Power { pub wheel_w: f64, pub shaft_w: Option<f64> }

/// `shaft_w` is `None` when the engine-side term cannot be trusted — no engine
/// data, or the clutch is slipping.
pub fn power(
    speed_ms: f64, accel_ms2: f64,
    engine: Option<EngineState>,          // ω and ω̇ in rad/s and rad/s²
    load: &RoadLoad, c: &Conditions,
) -> Power;

pub struct EngineState { pub omega: f64, pub omega_dot: f64 }

/// Ratio plateaus learned from the car's own steady-state data, per gear label.
pub struct Ratios(std::collections::BTreeMap<String, f64>);
impl Ratios {
    pub fn learn(engine: &Track, speed: &Track, gear: &States) -> Ratios;
    /// True when the measured ratio is more than 5 % from the gear's plateau,
    /// or below the speed floor where a ratio means nothing.
    pub fn slipping(&self, gear: &str, engine_omega: f64, speed_ms: f64, radius_m: f64) -> bool;
}
```

**Required behaviour, each a test:**
- `air_density(101.325, 15.0)` is **1.2250 kg/m³** to four significant figures — the ISO 2533
  sea-level value. This is the anchor: it catches a wrong `R`, a K/°C slip and a kPa/Pa slip at
  once. Do **not** test the formula against itself.
- `deltas` scales as `1/(m·r²)`: the same inertias on a 1000 kg car with 0.28 m wheels give
  visibly larger coefficients than on 1400 kg / 0.313 m.
- The exact engine-side term equals the ratio-based `δ₂·ξ²·a` while the clutch is locked
  (assert on a synthetic locked case, both forms, term for term).
- **A synthetic launch with the engine held at 2200 rpm while the car crawls produces
  `shaft_w == None`** — this is the defect the design exists to avoid: the ratio-based form
  reports 330 kW there.
- The shaft term goes negative during a synthetic upshift.
- `Ratios::learn` recovers plateaus from a trace without any ratio table in the source.

## Task 4 — the coastdown (`measure/coastdown.rs`)

Read spec §0 (The coastdown, inside setup).

**Files:** Create `crates/vagcan/src/measure/coastdown.rs`.

```rust
/// One accepted coast: speed against time, and the conditions it happened in.
pub struct Pass { pub speed: Track, pub rho: f64, pub mass_kg: f64 }

pub struct Fit { pub cda: f64, pub crr: f64, pub rms_kmh: f64 }

/// Closed-form v(t) = v_c·tan(arctan(v₀/v_c) − t/τ), fitted by Gauss-Newton
/// directly to the speed samples — no differentiation, and therefore no
/// smoothing window to argue about.
pub fn fit(pass: &Pass, delta1: f64) -> Result<Fit, Reject>;

pub struct RoadLoadResult {
    pub cda: f64, pub crr: f64,
    pub implied_grade_percent: f64, pub implied_wind_ms: f64,
}

/// Two reciprocal passes. Grade cancels exactly; the wind's w² term does not and
/// lands one-signed in Crr, so both are reported rather than merely used.
pub fn combine(a: &Fit, b: &Fit, mass_kg: f64, rho: f64, delta1: f64)
    -> Result<RoadLoadResult, Reject>;

pub enum Reject {
    OnlyOnePass,
    Disagreement { crr_percent: f64, limit: f64, implied_grade_percent: f64, implied_wind_ms: f64 },
    Residual { rms_kmh: f64, limit: f64 },
    TooNarrow { span_kmh: f64 },
}

/// Pass detection over a live stream: opens above `from_kmh` with the pedal at
/// zero and the selector in neutral, closes at `to_kmh`, and discards on pedal,
/// selector, rising speed or a braking-shaped deceleration step.
pub struct Detector { /* … */ }
pub enum Event { Opened, Closed(Pass), Discarded(&'static str) }
impl Detector {
    pub fn new(from_kmh: f64, to_kmh: f64) -> Self;
    pub fn on_sample(&mut self, t: Seconds, speed_kmh: f64, pedal_pct: Option<f64>,
                     selector: Option<&str>) -> Option<Event>;
}
```

**Required behaviour, each a test:**
- Synthetic coastdown with known `CdA`/`Crr` integrated from the ODE, sampled at 20 Hz with
  jittered timestamps and a 50 ms hold: `fit` recovers both within a stated tolerance.
- **A 1 % grade leaves the single-pass residual essentially unchanged while moving `Crr` by
  tens of per cent** — assert that, so nobody reintroduces "R² catches a slope".
- `combine` on a reciprocal pair with a 1 % grade returns the true coefficients and an
  `implied_grade_percent` near 1.
- `combine` with a 5 m/s wind returns `Crr` high by `½ρ·CdA·w²/(m·g)` (≈ +6 %) and an
  `implied_wind_ms` near 5 — the wind does **not** cancel and the test says so.
- One pass alone is `Reject::OnlyOnePass`.
- `Detector` discards on a braking step, on pedal movement, on the selector leaving neutral,
  and on rising speed, each with its own reason string.

## Task 5 — channel resolution (`measure/channels.rs`)

Read spec "Two kinds of number", §2.

**Files:** Create `crates/vagcan/src/measure/channels.rs`.

```rust
pub struct Resolved {
    pub key: &'static str, pub request: u16, pub did: u16,
    pub def: vag_data::catalog::MeasurementDef,
}
pub struct Set {
    pub leading: Resolved,            // the speed channel, and the unit that owns it
    pub leading_batch: Vec<Resolved>, // everything on that unit
    pub background: Vec<Resolved>,
    pub cross_check_speeds: Vec<Resolved>,
}
pub struct Missing { pub key: &'static str, pub tried: Vec<String> }

/// Resolve by catalog *name*. `full` adds the barometer and the ambient sensor,
/// which exist only to feed the power model and are not polled otherwise.
pub fn resolve(store: &CatalogStore, units: &[UnitIdentity], full: bool)
    -> Result<Set, Vec<Missing>>;
```

**Required behaviour:**
- Not one identifier literal in the file. Names only.
- The leading unit is whichever unit owns the finest speed channel: among name matches, the
  smallest `Scaling::Linear` factor wins, ties broken by unit id, and the winner is reported
  as `"7E1:F40D"` for `config.speed_source`.
- A catalog store missing speed yields `Missing { key: "speed", .. }` naming what was tried.
- Test against a **synthetic** catalog directory whose identifiers differ from the reference
  car's, proving the resolution is by name. Then a second test against the repository's own
  `catalogs/vehicles` as the reference case, in the style of `plan.rs`'s `reference()` helper.
- Values are read through `MeasurementDef::interpret` / `describe`; `Channel::render` is never
  called, because it returns `"… (raw)"` for the unproven and that class does not exist here.

## Task 7 — the state machine (`measure/session.rs`)

Read spec §1, §2 (rate propagation).

```rust
pub enum State { Idle, Arming { since: Seconds }, Armed, Running, Finished, Paused }
pub enum Command { PauseTrigger, Cancel, Save }
pub enum Event { Armed, Started(Seconds), MarkClosed(Mark), Finished(Run), Aborted(Run), Degraded }

pub struct Session { /* … */ }
impl Session {
    pub fn new(marks: Vec<(u32, u32)>, ring_seconds: Seconds) -> Self;
    /// The only entry point. Time is a parameter — never `Instant::now()` —
    /// which is what makes every test below runnable without a car.
    pub fn on_sample(&mut self, t: Seconds, s: SampleSet) -> Vec<Event>;
    pub fn on_command(&mut self, c: Command) -> Vec<Event>;
    pub fn state(&self) -> State;
}
```

**Required behaviour:** arming needs a **raw zero** held one second (the raw integer, not a
scaled float); `--speed-scale` is applied at ingest, before mark detection; the ring buffer
keeps 3 s before t0; a run ends at the top mark, on `Cancel`, or on speed returning to zero
(flagged aborted, keeping the marks that closed); a second standstill re-arms; `PauseTrigger`
prevents arming without losing the previous run; a rate below the floor emits `Degraded` once.

## Task 8 — the results table (`measure/report.rs`)

Read spec §4 (results table), §3a.

print as a one-signed range (`6.12 … 6.42 s`), rolling marks as a single number with a real ±.

## Hardware checkpoints

1. `measure` on a stationary car: identification, the channel check, arming, `WAITING`/`ARMED`.
2. One run to 50 km/h on a quiet road: marks, the tone, the results table, the saved file.
3. `measure setup` through both coastdown passes: the fit, the implied grade and wind.
4. `measure --full`: a power figure, checked for sanity against the car's rated output.
