# Что именно нужно блоку J500 — техническая спецификация

Одностраничник для сервиса, поставщика ПО или частника с ODIS. Всё, кроме
последнего раздела, прочитано с самой машины; источники и обстоятельства — в
[`eps-j500-report-ru.md`](eps-j500-report-ru.md).

---

## 1. Машина

| | |
|---|---|
| Модель | Škoda Octavia III, платформа MQB |
| Тип шасси | `NE-SK37` (`3Q0`) |
| VIN | `XW8AD4NE9JH008917` |
| Двигатель / КП | 1.8 TFSI (`8V0906264H`) / DQ200 (`0CW300041G`) |
| Пробег | ~212 815 км (август 2026) |

## 2. Блок (адрес 44, диагностический id `0x712`)

Прочитано с машины:

| идентификатор | значение | что это |
|---|---|---|
| `F187` | `5Q0909144S` | номер детали по ПО — **сейчас** |
| `F187` | `5Q0909144T` | он же **до вмешательства сервиса** |
| `F191` | `5Q0909144R` | номер детали по железу |
| `F189` | `1063` | версия ПО — **сейчас** (было `1072`) |
| `F1A3` | `129` | версия железа |
| `F1A2` | `013144` | индекс набора данных |
| `F197` | `EPS_MQB_ZFLS` | компонент (ЭУР Bosch/ZF) |
| `F19E` | `EV_SteerAssisMQB` | имя ODX-описания |
| `1923` | `01 00 00 00 00 00` | **ссылка на набор данных — пусто** |
| `1923` | `01 00 28 61 D7 E9` | она же у исправного блока, до отказа |

Смежный блок, влияющий на процедуру: ESC `5Q0 614 517 AQ`, ПО `0400` — уровень
достаточный, предварительное обновление **не требуется**.

## 3. Что произошло с прошивкой

Сервис перепрошил блок с `T`/`1072` на `S`/`1063`. Это **откат внутри того же
семейства**, а не обновление. По имеющимся сведениям ветки `L, M, P, R, S, T`
совместимы между собой по параметрии и несовместимы с `AB`; `AA` совместима с
`AB`. Если это так, текущая прошивка `S` не препятствует вводу в эксплуатацию, и
возвращать `T` необязательно.

Известные версии для детали `5Q0 909 144`:

| суффикс | версия ПО |
|---|---|
| `H` | 1021 |
| `P` | 1043 |
| `R` | 1061 |
| `S` | **1063 ← стоит сейчас** |
| `T` | **1072 ← стояла изначально** |
| `AA` | 1081 |
| `AB` | 1082 |
| `YF` | 9999 (базовая/сбросовая) |

## 3a. Потолок версии и правильная цель (установлено 2026-08-03)

**Выше `AB` / 1082 для детали `5Q0909144` не существует.** Две независимые
таблицы версий сходятся и обрываются на нём; файлы датированы 2018 годом.
`YF` / 9999 — не версия, а базовый образ: он идёт первой ступенью (`H2`), поверх
ложится основная прошивка (`H1`).

Порядок прошивки — **`H2 → H1`**, обе части допустимо залить в одном сеансе
ODIS Engineering. (Для старых веток встречается запись `H2 → H7 → H1`; для 1082
указана короткая цепочка. Уточнить у исполнителя перед началом.)

**`AB` — не только потолок, но и правильная цель**, по двум причинам:

* Параметрия семейств `L…T` и `AA`/`AB` **несовместима между собой**. Писать
  параметрию придётся в любом случае — своей у блока нет, — поэтому переход в
  семейство `AB` не стоит ничего.
* Прошивка **старых веток теряет параметрию** («слетает»), а 1082 её
  **сохраняет**. Встав на `AB`, блок перестаёт терять набор данных при будущих
  обновлениях. Это же объясняет, почему возврат на `T` — неверное направление.

**Ловушка с номерами деталей.** В ходящих подборках встречаются `3Q0909144K`
/ 5072, `3Q0909144M` / 5082, `5QF909144B` / 5582. Числа выше, но это **другие
детали** (Passat, Kodiaq, TT RS) на другом железе. Ориентир только по
`5Q0909144`.

## 3b. Какой набор данных подходит и как это проверить

Для ветки `AB` / 1082 под Octavia 1.8 существует **ровно один** вариант:

```
44_5Q0909144AB_1082_V03935281LB_Octavia_1.8_T0_05_17.01.2018.xml
```

Альтернативы на этой ветке нет, поэтому вопрос подбора здесь снимается. Он
возникает на других ветках: под Octavia 1.8 на `AA` перечислены **два** разных
набора (`V03935273WB` и `V03935278B`), а на `T` / 1072 они ещё и разделены по
приводу — `V03935242GP` для 4x2 и `V03935242GR` для 4x4. Машина
переднеприводная, то есть `4x2`.

**Чем ключуется набор — установлено.** Не VIN. Имена файлов несут внутренний
номер ZF (`V0393…`), модель, двигатель, привод и код типа; VIN в них
отсутствует. Это подтверждает версию из §7a: набор ключуется **конфигурацией**,
а сервер лишь выводит её из VIN.

**Формат набора и способ проверить кандидата.** Публичный разборщик
(«MQB EPS Dataset Viewer») читает и XML, и сырой образ. Набор — **8192 байта**,
две половины по 4096, у каждой своя **CRC-32**, которую блок проверяет; сигнатура
`0000 A55A 5AA5 A55A`, ревизия `$Rev:: 590`, цепочки таблиц LUT, значения в
формате Q12, критичные кривые продублированы по два-три раза как мера
целостности.

Во второй половине лежит **build tag `T00517.01.201803`** — то есть `T0`, `05` и
дата из имени файла берутся **изнутри набора**. `T0` — идентификатор типа, а не
обозначение коробки, как читают на форуме.

Практический вывод: **любой предложенный файл проверяется до записи** —
сходятся ли обе CRC и совпадает ли build tag с ожидаемым. Это превращает
подбор из лотереи в проверку и не требует ни оборудования, ни машины.

## 4. Что требуется сделать

**Ввод в эксплуатацию блока 44 — `Inbetriebnahme`.** Не прошивка: прошивку уже
сделали, и она проблему не решила, потому что набор данных пишется отдельной
процедурой.

Порядок:

1. `Inbetriebnahme` блока 44 в ODIS. Записывает параметрию — тип рулевого
   механизма, передаточное отношение, характеристику усиления, данные по осям и
   шинам, привязку к машине.
2. Если SVM по VIN предложит обновление ПО — с параметрией **соответствующей
   ветки**. Ветку не подбирать вручную.
3. После того как уйдёт внутренняя ошибка — калибровка датчика угла `G85`
   (`IDE05744`). Колёса прямо в пределах ±2.5°, развал-схождение в допуске,
   двигатель заведён.
4. Стереть коды в блоках 44, 03, 09, 10, 01 и проехать прямо.

## 5. Обязательные условия

| условие | почему |
|---|---|
| **Зарядное устройство на клеммах** | прерывание записи даёт ровно ту ошибку контрольной суммы, которая уже есть |
| **Проводной интерфейс** VAS 5054A / 6154 или совместимый J2534 | по бюллетеню TPI 2053681/3 связь по Bluetooth или Wi-Fi может оборвать процедуру |
| Не Bluetooth, не Wi-Fi | то же |
| Кабель VCDS **не подходит вообще** | Ross-Tech прямо пишет, что их интерфейсы ODIS не поддерживают. **HEX-NET тоже не подходит** — он не умеет притворяться простым pass-thru; ранее в этих заметках было сказано обратное, это исправлено |

**Отсутствие ODIS Engineering поблизости — не препятствие.** Сеанс проводится
удалённо: специалист подключается по интернету к ноутбуку рядом с машиной, а к
машине идёт только интерфейс. Из этого следует, что покупать нужно **интерфейс**,
а не искать исполнителя в своём городе. Названные в обиходе рабочие варианты —
VAS 5054A, VAS 6154, VNCI 6154A; подключение **только по USB**.

И первым делом стоит спросить про **онлайн-доступ (SVM)**: при нём набор данных
приходит с серверов VW по VIN, и вопрос с файлом отпадает целиком.

## 6. Текущие ошибки блока

```
229504  B2000 00   Неисправен блок управления      failed now, лампа, 50 проявлений
 13824             (появилась после прошивки)      50 проявлений
 26885             Ограничение комфорта            23 проявления
```

У всех — пробег `0` и неустановленное время: блок пишет их при старте, ещё не
получив ни пробега, ни часов. Пятьдесят проявлений = при каждом включении
зажигания.

## 7. Наблюдаемое поведение

* до прошивки — красный значок, помощи нет;
* после прошивки — **жёлтый** значок (ограничение функции, а не отказ);
* после снятия клеммы — снова красный.

Блок, который не переживает потерю питания, потому что при старте ему нечего
прочитать. Это картина отсутствующего набора данных, а не разрушенной платы.

## 7a. Что выяснилось про доступ к ПО (проверено 2026-08-03)

**erWin закрыт для частных лиц** с 18 декабря 2025 года — теперь только для
юридических. Старые подписки дорабатывают до конца срока, новых частных не
продают. Совет «купить суточную подписку», который был здесь раньше, снят.

**Ввод в эксплуатацию офлайн — раздельный ответ:**

* **ODIS Service без онлайна — нет.** Не запускает SVM: набор данных
  запрашивается с серверов VW прямо во время сеанса.
* **ODIS Engineering — механически да.** В нём есть функция `010 — передача
  данных` с выбором файла и кнопкой записи; существует опубликованное
  руководство именно по параметрированию характеристики усилителя. Работает с
  локальным файлом.

**Набор данных нельзя вычитать из машины** никаким инструментом — значит и
скопировать с донора невозможно.

**Чем ключуется набор — источники расходятся.** Одни говорят «по VIN» (запрос
уходит на сервер вместе с VIN), другие — и это реально ходящие файлы — названы
по модели и номеру детали, без VIN, и используются как шаблоны. Наиболее
вероятное примирение: набор ключуется **конфигурацией автомобиля** (тип рейки,
передаточное отношение, данные по осям и шинам, характеристика усиления), а
сервер лишь выводит её из VIN.

Практический вывод из этого — важный: чужой файл, скорее всего, **запишется**,
но никто не сможет сказать, тот ли это вариант конфигурации. Неверная
характеристика усиления на живой рейке — это не «не заработает», это «заработает
не так». Запрет из §9 остаётся в силе и теперь обоснован не осторожностью, а
механизмом.

## 8. Границы того, что установлено

* **Совместимость веток `L…T` между собой** взята из открытых источников, а не
  проверена на этой машине. Перед процедурой стоит подтвердить по SVM.
* **Одобрит ли SVM ветку `AB` на этом железе** (`F191` `5Q0909144R`, версия
  железа `129`) — не установлено. Публичной матрицы совместимости VW нет; это
  решает SVM, и именно он ни разу не запускался. Ветку `AB` называют целью
  открытые источники, а не завод.
* **Цепочка файлов для 1082** — `H2 → H1` по одному источнику, тогда как для
  старых веток тот же источник даёт `H2 → H7 → H1`. Подтвердить у исполнителя.
* **Набор данных не читается из блока.** Это не наблюдение, а свойство:
  с машины сняты 48 идентификаторов общим объёмом 382 байта — паспорт, а не
  данные. Сам набор — 8192 байта, и `1923` содержит шестибайтную **ссылку** на
  него, а не его содержимое. Поэтому снять набор с донора невозможно, и
  восстановить его из частичных публичных выкладок тоже: доступна примерно
  четверть образа (только кривые), а обе половины закрыты CRC-32.
* **Требует ли ввод в эксплуатацию J500 статуса GeKo** или достаточно онлайна —
  не установлено. GeKo в источниках привязан к иммобилайзеру и защите
  компонентов; про рулевое ничего не сказано ни за, ни против.
* **Восстановит ли запись набора через ODIS-E значение `1923`** — не проверено. А
  это и есть критерий успеха.
* **Поддерживается ли сочетание `S`/1063 на железе `R`/129** — публичной матрицы
  совместимости VW нет. Именно это решает SVM, и именно он не запускался.
* **Покрывает ли бизнес-подписка erWin операцию для адреса 44** — не установлено.
* **Оживёт ли блок после ввода в эксплуатацию** — неизвестно. Оценка примерно
  50–60 %: за это говорит то, что после первого отказа блок восстанавливался
  перезапуском, против — что `B2000` есть нарушение целостности памяти.

## 9. Чего делать не следует

* Не заливать прошивку или параметрию неизвестного происхождения. У блока уже
  нарушена целостность данных; запись не той ветки превращает шанс на
  восстановление в ноль, а сейчас блок хотя бы отвечает и опознаётся.
* Не выполнять `Inbetriebnahme` по беспроводному интерфейсу.
* Не гонять калибровку угла до устранения внутренней ошибки — она обрывается
  сама, с записью `ASC_CTRL_SAS_HL_ERR`.
* Не менять датчик угла и рулевую колонку по коду `0297` у ESC: это следствие,
  он появился после отказа усилителя.
* Не покупать б/у блок в надежде обойтись без процедуры. Рейки MQB заказываются
  под VIN и приходят запрограммированными; б/у придёт с чужим набором данных и
  потребует того же самого ввода в эксплуатацию. Это покупка второго экземпляра
  той же проблемы.

## Одной строкой для приёмки

> Škoda Octavia III, VIN `XW8AD4NE9JH008917`. **Блок 44, J500.**
>
> **Исходно:** деталь `5Q0 909 144 T`, ПО `1072`, железо `5Q0 909 144 R`, версия
> железа `129`, индекс набора `013144`, компонент `EPS_MQB_ZFLS`, ODX
> `EV_SteerAssisMQB`.
> **Сейчас, после прошивки в другом сервисе:** деталь `5Q0 909 144 S`, ПО `1063` —
> откат на другую ветку, подобранный вручную вместо подбора по VIN.
>
> **Неисправность:** утерян набор данных. Идентификатор `1923` был
> `01 00 28 61 D7 E9`, стал `01 00 00 00 00 00` и не восстановился, в том числе
> после прошивки — то есть `Inbetriebnahme` не выполнялась. Коды: `229504 B2000 00`,
> `7680 B200F F0`, `16136 B1168 F2`.
>
> **Что нужно, дословно:** **`Inbetriebnahme` (ввод в эксплуатацию) блока J500,
> адрес 44, в ODIS с онлайн-доступом / SVM.** Не прошивка. Не базовые установки.
> Не стирание — всё три уже пробовали.
>
> **Условия (TPI 2053681/3):** зарядное на клеммах; **проводной** интерфейс по
> USB — VAS 6154 или VAS 5055; **без Bluetooth и Wi-Fi**. Прерванная запись на
> блоке без набора данных хуже нынешнего состояния.
>
> **Версия ПО:** та, которую выберет **SVM по VIN**. Прошу не подбирать версию
> вручную снова. Если SVM недоступен, целевая ветка — **`AB` / 1082**: это
> потолок для этой детали, и единственная, которая не теряет параметрию при
> прошивке. Порядок `H2 → H1`. Параметрия при этом **обязательно ветки `AB`** —
> с `L/M/P/R/S/T` она несовместима. Для Octavia 1.8 на этой ветке существует
> ровно один набор, `V03935281LB`, так что подбирать нечего.
>
> **Проверка файла до записи:** набор — 8192 байта, две половины по 4096, у
> каждой своя CRC-32. Прошу убедиться, что обе сходятся и что build tag второй
> половины соответствует набору, прежде чем писать его в блок.
>
> **До начала прошу прочитать:** **Symptomnummer** и `Param_Kfa` у `B200F F0` и
> `B2000 00` в расширенных условиях окружения — заводские бюллетени по этому
> значению расходятся между «лечится программно» и «менять рейку». И проверить,
> отвечают ли идентификаторы `1920`, `1921`, `1922` в расширенной сессии.
>
> **После:** калибровка датчика угла `G85`, колёса прямо в пределах ±2.5°,
> развал-схождение в допуске, двигатель заведён. Затем стереть ошибки во всех
> блоках и проехать прямо.
>
> **ESC `5Q0 614 517 AQ` / `0400` — уровень достаточный, обновление не требуется**
> (TPI 2069273/3).
>
> **Критерий приёмки:** после процедуры `1923` должен читаться ненулевым. Если
> `B2000` возвращается **после выполненного** ввода в эксплуатацию — тогда
> заключение о замене обосновано, но не раньше.
